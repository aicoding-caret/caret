# 문서 조직화 워크플로우

프로젝트 문서의 구조화 및 관리 방법입니다.

## 문서 구조

### 이중 디렉토리 아키텍처
```
.agents/                    # AI용 (영어, 토큰 최적화)
├── context/               # 빠른 참조 (50-80줄)
├── workflows/             # 상세 절차 (100-250줄)
│   └── atoms/             # 재사용 빌딩 블록
├── skills/                # AI 스킬
└── hooks/                 # 자동화 훅

.users/                     # 사람용 (한국어, 상세)
├── context/               # 상세 가이드
├── workflows/             # (.agents/ 미러링)
├── skills/                # (.agents/ 미러링)
└── hooks/                 # (.agents/ 미러링)
```

### 1:1 미러링 원칙
- `.users/` 구조는 `.agents/`를 정확히 미러링
- `.agents/`는 영어 (토큰 효율)
- `.users/`는 사용자/팀 언어 (상세 설명)

## 문서 유형

### Context 문서
- 빠른 참조용
- 50-80줄 권장
- 핵심 정보만 포함

### Workflow 문서
- 단계별 절차
- 100-250줄 권장
- 예제 코드 포함

### Atoms
- 재사용 가능한 작은 단위
- 여러 워크플로우에서 참조
- 20-50줄 권장

## 문서 작성 가이드

### 언어
- `.agents/`: 영어, 간결
- `.users/`: 팀 언어, 상세

### 형식
```markdown
# 제목

## 개요
간단한 설명

## 단계
1. 첫 번째 단계
2. 두 번째 단계

## 참고
추가 정보

## 미러링 정책
(항상 포함)
```

### 코드 예제
- 실제 동작하는 코드만
- 주석으로 설명 추가
- 언어 태그 명시
