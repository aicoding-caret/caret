# 검증 단계 - 테스트 → 컴파일 → 실행 시퀀스

모든 변경 후 필수 검증 시퀀스입니다.

## 핵심 원칙
**모든 변경은 완료 전 세 가지 검증 단계를 모두 통과해야 합니다**

## 단계 1: 테스트 검증
**변경 범위에 따라 적절한 테스트 실행**

### 백엔드 변경:
```bash
# 백엔드 유닛 테스트 (Mocha)
npm run test:unit

# 프론트엔드 테스트 (Vitest)
npm run test:webview

# VSCode 통합 테스트
npm run test:integration
```

### 전체 테스트 커버리지:
```bash
# 포괄적인 테스팅이 필요할 때
npm run test
npm run test:coverage
```

### 테스트 요구사항:
- [ ] 모든 기존 테스트가 여전히 통과
- [ ] 새 기능에 테스트 존재 (`/tdd-cycle` 준수)
- [ ] 테스트 실패나 경고 없음

## 단계 2: 컴파일 검증
**TypeScript 컴파일 성공 확인**

```bash
# 주요 컴파일 체크
npm run compile

# 타입 체킹
npm run check-types

# 프로토콜 버퍼 생성 (proto 파일 변경 시)
npm run protos
```

### 컴파일 요구사항:
- [ ] TypeScript 오류 제로
- [ ] 모든 타입 정의 유효
- [ ] Import/export 문 정확
- [ ] 프로토콜 버퍼 성공적으로 생성 (해당 시)

## 단계 3: 실행 검증
**실행 환경에서 실제 기능 테스트**

### 개발 테스팅:
```bash
# 개발 환경 시작
npm run watch
# VSCode에서 F5를 눌러 익스텐션 실행
```

### 수동 검증 체크리스트:
- [ ] 익스텐션이 오류 없이 로드
- [ ] 새 기능이 예상대로 작동
- [ ] 기존 기능에 영향 없음
- [ ] 콘솔 오류나 경고 없음
- [ ] UI가 올바르게 렌더링 (해당 시)

## 실패 대응 프로토콜

### 테스트 실패 시:
1. **진행하지 않음** - 테스트 이슈 먼저 수정
2. 테스트 출력에서 구체적인 실패 확인
3. `/tdd-cycle` 원칙 적용하여 수정

### 컴파일 실패 시:
1. **진행하지 않음** - TypeScript 오류 해결
2. import 경로와 타입 정의 확인
3. 필요시 proto 파일 재생성

### 실행 실패 시:
1. **진행하지 않음** - 런타임 이슈 디버그
2. 브라우저 콘솔에서 오류 확인
3. 익스텐션 활성화 및 기능 검증

## Modification 시스템과의 통합
**`/modification-protocol` (L2 수정) 사용 시:**
- 검증 실패 시: 원본 코드로 되돌리기
- 이슈 수정 후 검증 시퀀스 재시도
- 검증 실패한 변경은 절대 커밋하지 않음

## 관련 워크플로우
- `/tdd-cycle` 완료의 필수 부분
- 모든 `/modification-levels`에 필수
- 안전한 실험을 위해 `/modification-protocol` 사용

## 일반 가이드라인
이 검증 시퀀스는 깨진 코드가 커밋되거나 배포되는 것을 방지합니다.

세 단계 접근법은 적절한 단계에서 다른 유형의 이슈를 잡아냅니다.

절대 검증을 건너뛰지 마세요 - 이슈를 조기에 잡아 시간을 절약합니다.
